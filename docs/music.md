# 配乐

配乐全部由 Agent 当场写 Web Audio 代码合成：没有内置曲库，没有兜底引擎。

> 返回 [README](../README.md)

---

音轨由 Web Audio 程序化合成：不引入音频素材，不访问网络，也不调用音频生成模型。
合成在 `OfflineAudioContext` 中离线完成，长度与影片严格一致，并与画面共用同一时钟。

## 配乐是必填项

`save_animation` 的 `score_js` **必须提供**。插件里没有任何「拿不到就用现成配乐顶上」的分支：

| 情况 | 结果 |
|---|---|
| 没传 `score_js` | 保存直接报错，动画不会落盘 |
| `score_js` 里没建任何音频节点 | 保存直接报错 |
| 浏览器渲染不出声音 | 卡片提示原因，导出被拦下 |

返工时可以传 `base_id` 沿用上一版的配乐，但首版必须自带 `score_js`。这样每一条片子的
声音都是为它现写的，不会出现「几条片子听起来一模一样」的情况。

## 配乐代码长什么样

```js
// save_animation 的 score_js 形参：ctx, dest, bed, duration, cuts, cues, beats, rand, hz
function pluck(freq, at, dur, vol) {      // Karplus-Strong 拨弦，像古筝
  const n = Math.floor(ctx.sampleRate / freq);
  const buf = ctx.createBuffer(1, n * 2, ctx.sampleRate);
  const d = buf.getChannelData(0);
  for (let i = 0; i < d.length; i++) d[i] = rand() * 2 - 1;
  ...
}

for (let t = 0; t < duration; t += 0.5) pluck(hz(57 + pentatonic()), t, 1.2, 0.08);  // 铺底 → bed
for (const t of cuts) drum(t, 0.7);                                                  // 卡点 → dest
```

| 环节 | 谁做的 |
|---|---|
| 画面 HTML + Canvas | Agent 现写 |
| 配乐合成代码 | Agent 现写 |
| 编译并渲染成音频 | 浏览器执行 |

音色完全由 Agent 决定：要古筝就写拨弦算法，要竹笛就写噪声过共振峰，要鼓就写固定频率正弦
加噪声瞬态。没有任何音色预设表，也没有关键词匹配。

## 两条总线：bed 与 dest

渲染时两条总线都会给到配乐代码：

| 形参 | 接什么 | 会被怎么处理 |
|---|---|---|
| `bed` | 持续的旋律、和弦、律动 | 每个卡点前后被侧链下压，让位给重音 |
| `dest` | 重音、打击乐、转场冲击 | 原样输出，不衰减 |

分线是卡点能不能听出来的关键。铺底和重音都接到同一个总线，就没有空隙让重音落进去，
卡点会被自己的伴奏淹掉。

## 一条硬禁令：不许低频扫频

**任何配乐都不许把正弦从一两百赫兹一路滑到三四十赫兹。** 这种声音听感像放屁，不是鼓。

底鼓要「咚」，就给一个**固定频率**的低正弦加一层鼓皮噪声，让**包络**去做冲击，不要让
**频率**去滑。提示词里写死了这条，没有例外。

## 28 条音色配方

28 条音色配方在 [工艺参考](references.md) 的 `timbre` 里（`get_reference("timbre")` 取），
已逐个试听校准，覆盖原声与电子两大类：

| 类别 | 条目 |
|---|---|
| 打击乐 | 底鼓、军鼓、闭合踩镲、开镲、通鼓、吊镲、808 底鼓、四踩律动 |
| 拨弦与弦乐 | 古筝拨弦、清音吉他、失真主音、弦乐铺底、低频贝斯 |
| 管乐与音块 | 竹笛、钟铃、马林巴 |
| 电子 | 酸性贝斯 303、超级锯齿、合成拨弦、琶音、FM 贝斯、门限铺底、芯片方波、抖动贝斯、侧链泵动 |
| 转场 | 上行扫频、下坠噪声、落重音 |

每条都写明「听感」和一个具体做法，例如：

| 音色 | 听感 | 做法 |
|---|---|---|
| 底鼓 kick | 低频「咚」，音高不滑动 | 噪声过 220Hz 带通衰 0.05s，叠固定频率正弦衰 0.13s |
| 酸性贝斯 303 | 锯齿过强共振，每个音「呜」一下 | 锯齿过 Q=11 状态变量滤波，截止 240→2840Hz 指数衰 0.075s |
| 古筝拨弦 | 明亮拨弦，金属余韵 | Karplus-Strong，循环反馈 0.998 |

另外附了三个完整代码示例：Karplus-Strong 拨弦、状态变量滤波器扫频、超级锯齿叠加。

同一份参考里还有**编曲**部分：同一时刻最多 4 层、密度曲线、卡点处的三种处理、收尾衰减。

校准用到的试听素材在 [`docs/sound-samples/`](sound-samples/index.html)，可以直接打开逐条试听。

## 卡点

卡点落在哪，由写配乐的人决定：`beats` 是 Agent 从自己的动画代码里导出的精确时刻，
`cuts` 是分镜切点，`cues` 是镜头内部的重点动作。把声音事件用 `start(t)` 直接落在这些秒数上，
就是卡点。

| 依据 | 精度 | 说明 |
|---|---|---|
| `beats` | 毫秒级 | 从动画代码导出，最可信，优先用它 |
| `cues` | 毫秒级 | 分镜里标注的镜头内部动作 |
| `cuts` | 秒级 | 分镜切点，比较粗 |

重音要能穿透，靠的是 `bed` 侧的侧链让位：卡点前 100ms 铺底下沉，重音直达 `dest`，
于是重音落在空隙里，而不是叠在同样响的铺底之上。

## 镜头内部的卡点

卡点不只发生在分镜之间。分镜的每个镜头可带 `cues`，标记镜头内部的关键视觉动作：

```json
{
  "start": 0, "end": 2, "scene": "粒子聚成标题",
  "cues": [
    { "time": 0.8, "type": "impact", "label": "标题砸下" },
    { "time": 1.6, "type": "rise",   "label": "能量聚拢" }
  ]
}
```

`save_animation` 也可以直接传 `cues`，与分镜里的合并生效。

## 自定义音频

卡片上可选择「更换音频」载入本地文件。文件仅在浏览器内混入，不上传，也不写回工作区；
短文件自动循环补满，末尾自动淡出。这是唯一一条「不是 Agent 写的配乐」还能进片子的路，
而且必须由用户主动选文件。

## 可复现性

配乐代码里可用的 `rand()` 是固定种子的可复现随机函数，所以同一段代码渲染出的音轨逐样本一致。
峰值留有余量，不削波。
